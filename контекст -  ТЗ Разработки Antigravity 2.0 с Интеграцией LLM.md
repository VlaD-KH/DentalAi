# **Техническое Задание: Архитектура и реализация автономной CAD/CAM системы Dental-MCP-Antigravity в среде Antigravity 2.0**

## **Архитектурный фундамент и парадигма мультиагентной среды**

Проектирование современных автономных производственных комплексов требует перехода от классической монолитной архитектуры программного обеспечения к децентрализованным мультиагентным средам. В основе разрабатываемого программно-аппаратного комплекса для автоматизированного проектирования и производства зубных протезов (Dental-MCP-Antigravity) лежит среда Antigravity 2.0. Данная платформа реализует передовую парадигму проектно-ориентированной разработки, в которой искусственные агенты функционируют поверх файловых систем, инструментов и задач с четко определенными границами доступа и ролями, преодолевая ограничения устаревших репозиторно-ориентированных рабочих процессов.  
Фундаментальная методология разработки комплекса базируется на концепции агентного цикла (agent-loop) и целеполагающего (goal-oriented) программирования. В отличие от традиционного линейного исполнения скриптов, система Antigravity 2.0 использует непрерывные циклы обратной связи и динамическое создание субагентов для параллельного решения сложных инженерных задач. Оркестрация процессов выполняется на базе специализированного ядра, где основной управляющей единицей выступает команда /goal. Эта директива инструктирует систему выполнять комплексную задачу до ее полного завершения без промежуточных прерываний на пользовательский ввод, опираясь исключительно на внутренние механизмы верификации и самокоррекции. Разработка и управление ведутся с использованием Antigravity CLI (agy) — легковесного, высокопроизводительного терминального интерфейса, который разделяет общее ядро с визуальной средой Antigravity IDE, обеспечивая бесшовную интеграцию между низкоуровневыми терминальными конвейерами и визуальным контролем исполнения.  
Глубокий анализ архитектуры показывает, что делегирование задач специализированным субагентам позволяет радикально снизить когнитивную и вычислительную нагрузку на центральный оркестратор. В контексте зуботехнической лаборатории это означает, что пока один агент занимается математическим парсингом 3D-сетки и извлечением линии уступа, другой субагент может параллельно генерировать элементы пользовательского интерфейса, а третий — компилировать управляющий G-код для фрезерного станка. Такая архитектура требует строгой регламентации каждого этапа жизненного цикла проекта, начиная от подготовки вычислительной среды и заканчивая финальной сборкой.

## **Инициализация вычислительной среды и автоматическая проверка ресурсов**

Для обеспечения строгой консистентности вычислений и соблюдения медицинских стандартов качества система должна быть полностью автономной и готовой к работе в изолированных условиях (air-gapped readiness). Первый этап работы комплекса заключается в автоматическом развертывании и валидации вычислительной среды специализированным агентом-инициализатором.  
При запуске системы агент выполняет низкоуровневый опрос аппаратного обеспечения. Обработка высокополигональных дентальных сеток, которые могут содержать сотни тысяч полигонов, а также инференс локальных диффузионных моделей сегментации требуют значительных вычислительных мощностей. Агент использует системные утилиты, доступные через локальный терминальный sandbox Antigravity, для верификации доступных ресурсов и адаптации конфигурации под текущее железо.

В случае обнаружения нехватки видеопамяти агент-инициализатор автоматически перенастраивает конфигурацию локальных моделей на использование алгоритмов квантования, таких как 4-bit AWQ, для предотвращения критических ошибок нехватки памяти (Out-Of-Memory) при загрузке визуальных моделей. После успешной валидации ресурсов система переходит к генерации и исполнению скриптов оболочки для автоматической загрузки зависимостей.  
Ядром программной инфраструктуры является контейнеризация. Агент инициализирует установку интерпретатора Python версии 3.11 и выше через высокоскоростной менеджер пакетов uv, что гарантирует строгую детерминированность дерева зависимостей. Параллельно разворачивается среда Node.js для последующей сборки клиентской части дашборда, основанной на библиотеках Three.js и Tailwind CSS. Инфраструктура искусственного интеллекта развертывается посредством образов docker-compose, включающих Triton Inference Server для высокопроизводительной обработки 3D-геометрии и фреймворк vLLM для управления пулом локальных языковых и визуальных моделей. Для обеспечения связи между моделями и физическими инструментами агент инсталлирует библиотеку FastMCP, которая выступает коммуникационной шиной данных.  
Поскольку целевая лаборатория ориентирована на европейский рынок, в частности на функционирование в Щецине (Польша), инициализатор конфигурирует систему в строгом соответствии с медицинским регламентом Medical Device Regulation (MDR EU 2017/745). Агент автоматически генерирует локальные реляционные базы данных для хранения партий материалов, таких как циркониевые диски Upcera 3D Pro Multi, создавая неизменяемый криптографический аудит-след для каждого изделия. Настраивается жесткая изоляция среды выполнения через параметр enableTerminalSandbox в конфигурационном файле settings.json, что предотвращает несанкционированную передачу медицинских данных за пределы локального контура лаборатории.

## **Подсистема интеграции LLM: Маршрутизация, API и локальные модели**

Критически важным аспектом архитектуры является реализация гибридной подсистемы больших языковых моделей. Для достижения баланса между экономической эффективностью, скоростью рассуждений и безопасностью конфиденциальных медицинских данных, система комбинирует вычислительную мощность проприетарных моделей по подписке (Google AI Pro, Claude) с надежностью локальных специализированных нейросетей.  
Механизмы подключения внешних LLM по API глубоко интегрированы в среду Antigravity. Платформа нативно поддерживает OAuth-авторизацию для безопасного взаимодействия с облачными экосистемами, исключая необходимость ручного управления открытыми текстовыми ключами в исходном коде. При первичной настройке агент инициирует команду авторизации, которая открывает системный веб\-браузер для прохождения потока Google Sign-In. После предоставления разрешений для выбранного облачного проекта, криптографические OAuth-токены надежно сохраняются в системном хранилище ключей (System Keyring) операционной системы. Это открывает мультиагентному рою доступ к флагманским моделям, включая Gemini 3.6 Flash, Gemini 3.5 Flash и Gemini 3.1 Pro.  
Подключение коммерческих подписок Anthropic реализуется через конфигурацию плагинов или внедрение токенов доступа в защищенные переменные окружения, такие как ANTIGRAVITY\_API\_KEY. Данный подход позволяет агентам бесшовно делегировать сложные задачи по генерации программного кода моделям Claude Sonnet 4.6 (thinking) и Claude Opus 4.6 (thinking), которые демонстрируют выдающиеся результаты в написании сложных архитектурных компонентов. Для интеграции сторонних серверов, требующих специфических заголовков авторизации, агент конфигурирует системный файл mcp\_config.json, определяя URL удаленных эндпоинтов и передавая токены стандарта Bearer, что обеспечивает прозрачную межсервисную аутентификацию.  
Параллельно с облачными API, система разворачивает кластер локальных моделей, образующих ядро AI/ML (AI/ML Core). Эти сети необходимы для задач, требующих нулевой сетевой задержки и гарантированного сохранения врачебной тайны при обработке 3D-сканов пациентов. Вектор локальной обработки геометрии включает интеграцию специализированных PyTorch-архитектур, таких как MeshSegNet, DilatedToothSegNet и DiffusionNet++. Данные модели обучены на масштабных стоматологических датасетах (например, Teeth3DS) и способны анализировать сырые полигональные сетки, вычисляя нормали поверхностей и кривизну для точной сегментации 15 классов зубов и десны согласно международной номенклатуре FDI. Восстановление утраченной анатомии окклюзионных поверхностей поручается локальной диффузионной модели CrownGen, в то время как визуальный контроль качества генерируемых рендеров осуществляется через локальные мультимодальные модели (VLM), такие как MiniCPM-V 2.6 или квантованная версия Qwen2.5-VL-7B-Instruct.  
Для управления этим разнообразным парком моделей внедряется сложная система динамической маршрутизации (Model Routing). Логика распределения задач фиксируется в конфигурационных файлах AGENTS.md и GEMINI.md, которые регламентируют границы применимости каждой LLM в рамках единого проекта.

Системные промпты задают строгие правила работы с этими моделями. Например, правило валидации resolve\_occlusal\_penetration безапелляционно предписывает, что любой агент, зафиксировавший толщину стенки реставрации менее установленного предела в 0.6 мм, обязан немедленно инициировать процедуру возврата задачи на доработку (Loopback), минуя этап подтверждения оператором. Подобная архитектура формирует децентрализованный, высокоэффективный рой, где быстрые модели выполняют диспетчерскую работу, графовые сети обрабатывают физику объектов, а мощные аналитические модели выступают в роли строгих верификаторов.

## **Разработка компонентов и генерация кода агентами**

Центральным процессом функционирования среды является непрерывный агентный цикл. Инициализация этапа разработки начинается с того, что главный агент-оркестратор анализирует входной дизайн-референс дашборда "Dental Autonomous Solo Lab OS" и декомпозирует его на атомарные задачи, распределяя их между субагентами.  
Первостепенной задачей является создание инструментов для связи языковых моделей с геометрическими алгоритмами. Агент-программист генерирует код специфических навыков (Skills) с использованием фреймворка FastMCP. Данный фреймворк позволяет превращать стандартные функции Python в узлы протокола Model Context Protocol посредством простого декорирования. Агент пишет реализацию функции сегментации, снабжая ее декоратором @mcp.tool. Встроенные механизмы FastMCP автоматически конвертируют аннотации типов и строки документации (docstrings) этой функции в строгие JSON-RPC схемы, которые мгновенно становятся понятны всем агентам в сети. Аналогичным образом генерируются инструменты для поиска линии уступа (detect\_margin\_line), использующие алгоритмы сглаживания Лапласа, и функции для математического расчета цементного зазора посредством эквидистантного смещения внутренней поверхности коронки на 35 микрон. Агенты также формируют систему динамических URI-идентификаторов (например, dental://scans/{order\_id}/upper\_mesh), что позволяет абстрагировать сложные пути файловой системы и предоставлять LLM унифицированный доступ к геометрическим ресурсам.  
Параллельно с разработкой математического ядра, агент, ответственный за пользовательский опыт (UI/UX Agent), приступает к генерации интерфейса дашборда. Опираясь на предоставленный графический референс, агент синтезирует компонентную базу с использованием современных веб\-технологий. Центральным элементом становится интерактивный 3D-вьювер, написанный на базе Three.js. Агент генерирует сложные WebGL шейдеры для отображения тепловой карты (Thickness Heat-Map), визуализирующей толщину стенок коронки. Логика шейдера настраивается таким образом, чтобы безопасная толщина (около 0.72 мм) отображалась зеленым цветом, а участки, склонные к сколам, окрашивались в предупреждающий красный градиент.  
Для боковых панелей управления агент создает компонент мониторинга "Рой AI-Агентов", который через WebSocket-соединение подписывается на логи сервера FastMCP и рендерит поток вызовов инструментов в реальном времени. Особое внимание агент уделяет строгому соответствию корпоративному стилю: применяются моноширинные шрифты JetBrains Mono для отображения логов, а цветовая палитра интерфейса жестко привязывается к заданным HEX-кодам, таким как глубокий темный фон \#0F1117 и неоновый акцент линии уступа \#00F0FF. Дополнительно генерируется виджет для управления раскроем циркониевых дисков (Zirconia Disk Nesting), визуализирующий процесс позиционирования коронок в заготовке диаметром 98.5 мм.  
Завершающим элементом кодогенерации является создание модулей аппаратной телеметрии и коннекторов для CAM-компиляции. Агент разрабатывает скрипты, интегрирующие протоколы промышленного интернета вещей (IoT), для получения телеметрии с 5-осевых фрезерных станков и печей синтеризации. Сгенерированные цифровые датчики на дашборде в реальном времени отображают критические параметры производственного процесса: скорость вращения шпинделя на уровне 45,000 RPM, температурный профиль печи, достигающий 1530°C, и давление в пневматической магистрали 6.4 Bar. В фоновом режиме агент формирует скрипты для экспорта производственных метаданных в форматы XML или JSON (.constructionInfo), обеспечивая бесшовную совместимость с популярными CAM-процессорами, такими как MillBox или hyperDENT.

## **Динамическая интеграция и плагинная архитектура (Hot-Swapping)**

Фундаментальным технологическим преимуществом среды Antigravity 2.0 является ее расширяемость и способность к интеграции новых компонентов "на лету" (hot-swapping). В традиционных системах добавление нового инструмента требует остановки сервисов и полной перекомпиляции проекта, однако мультиагентная архитектура обходит это ограничение благодаря структурированной системе плагинов.  
Все сгенерированные агентами инструменты, поведенческие скрипты и правила линтинга автоматически упаковываются в изолированные пространства имен, формируя плагины Antigravity. Агент-архитектор динамически создает необходимые директории в глобальном пути конфигурации платформы, типично располагающемся по адресу \~/.gemini/antigravity-cli/plugins/\<plugin\_name\>/. Архитектура такого плагина строго регламентирована и включает несколько ключевых компонентов. Обязательным элементом является файл plugin.json — манифест, описывающий метаданные расширения и содержащий ссылку на официальную схему валидации для обеспечения совместимости.  
Особую роль в динамической интеграции играет файл mcp\_config.json. Как только агенты завершают написание нового Python-инструмента и запускают для него локальный сервер, они обновляют этот конфигурационный файл, прописывая пути и аргументы запуска (например, параметры для вызова Docker-контейнера). Терминальная служба Antigravity CLI непрерывно мониторит данные конфигурации и, при обнаружении изменений, автоматически подхватывает новые узлы Model Context Protocol. Это позволяет мгновенно предоставлять новые инструменты в контекст всем активным субагентам без прерывания текущей сессии диалога.  
Для расширения функционала на уровне самого рабочего пространства агенты могут формировать локальные навыки (Skills). Размещая специализированные Markdown-файлы в директории .agents/skills/ (например, mdr\_validation.md), агенты определяют новые слэш-команды. При следующем обращении к консоли, интерфейс agy компилирует эти файлы, делая команду /mdr\_validation доступной для вызова. Логика интеграции также дополняется механизмом хуков, описываемых в hooks.json. Эти триггеры позволяют системе автоматически запускать утилиты форматирования кода (например, prettier) сразу после генерации нового UI-компонента или инициировать процессы топологической очистки сетки после завершения работы алгоритма сегментации.  
Такая гибкость поддерживается на уровне транспортного протокола. Платформа использует стандартный транспорт stdio для связи с локально порожденными процессами, что минимизирует накладные расходы на сериализацию, и транспорт HTTP (с поддержкой Server-Sent Events) для коммуникации с удаленными вычислительными узлами. Если в процессе обработки клинического случая агент-контроллер сталкивается со сложной геометрической аномалией, для которой не существует подходящего инструмента очистки, он автономно делегирует агенту-программисту задачу по написанию нового алгоритма. Программист генерирует код, регистрирует его через mcp\_config.json, и оркестратор продолжает выполнение задачи, используя новый навык. Этот процесс полностью инкапсулируется внутри защищенного контура выполнения (Terminal Sandbox), который использует нативные механизмы операционной системы (такие как nsjail или sandbox-exec) для предотвращения несанкционированного доступа скриптов к корневой файловой системе.

## **Автоматизированное тестирование и визуальный контроль (Vision)**

В сфере разработки программного обеспечения для медицинского приборостроения надежность системы имеет абсолютный приоритет. Для обеспечения безотказности генерируемых решений среда Antigravity 2.0 использует многоуровневую стратегию автоматизированного тестирования, опирающуюся на рой агентов-тестировщиков (QA Agent Swarm) и механизмы постоянной верификации локальных песочниц.  
Базовый уровень обеспечивается классическим модульным и интеграционным тестированием. Агенты автономно пишут и исполняют Unit-тесты для проверки математической корректности алгоритмов обработки геометрии. Тестированию подвергается топология выходных сеток: проверяется отсутствие не-многообразных ребер (non-manifold edges), пересекающихся граней и открытых дыр, что гарантирует абсолютную водонепроницаемость (watertight) модели перед отправкой на фрезерный станок. Дополнительные тесты имитируют кинематику челюсти для валидации окклюзионных конфликтов, строго проверяя, чтобы расчетное внедрение реставрации в зуб-антагонист не превышало допустимой погрешности в \-0.05 мм. Интеграционные конвейеры симулируют сквозное прохождение производственного заказа, от загрузки сырого STL-скана до финальной генерации G-кода, логируя изменения состояния в базах данных на каждом шаге.  
Революционным аспектом системы является подход к UI-тестированию. Вместо создания хрупких и нестабильных скриптов на базе селекторов (подобных Selenium), комплекс использует встроенные возможности интеграции с браузером (browser-in-the-loop) и мультимодальный анализ. Процесс визуальной валидации инициируется агентом Vision\_Tester, который запускает локальный веб\-сервер с только что сгенерированным дашбордом. Используя нативную команду /browser, агент рендерит пользовательский интерфейс в изолированном headless-режиме и осуществляет захват серии скриншотов.  
Полученные графические артефакты отправляются на анализ в мультимодальную визуальную модель (такую как Claude Opus 4.6 Vision или локальный инстанс Qwen2.5-VL), куда также передается исходный дизайн-референс. Визуальная модель выполняет глубокий семантический и пиксельный анализ результата. Проверяется типографика на предмет соответствия семействам шрифтов Inter и JetBrains Mono, сверяются HEX-коды критических статусных сообщений (например, подтверждается использование цвета \#FF3D00 для индикации системных ошибок), и валидируется общая архитектура сетки расположения виджетов. Наиболее ресурсоемкой задачей визуального агента является оценка интерактивного 3D-вьювера: модель анализирует отрендеренную тепловую карту толщины, подтверждая, что градиент математически корректно отражает области истончения коронки. Любые выявленные визуальные несоответствия формируют структурированный цикл обратной связи (Feedback loop), который немедленно направляется агенту-разработчику для внесения корректировок.

## **Автоматизированная сборка, документация и CI/CD**

Финальная стадия агентного цикла заключается в консолидации всех разработанных компонентов, генерации сопроводительной документации и подготовке проекта к развертыванию. Специфика медицинского программного обеспечения диктует необходимость исчерпывающего документирования архитектуры и процессов.  
Агент, выполняющий роль технического писателя (Technical\_Writer), сканирует всю сгенерированную кодовую базу, анализирует абстрактные синтаксические деревья (AST) Python-модулей и извлекает информацию из конфигурационных файлов FastMCP. На основе этих данных синтезируется подробная техническая документация. Для визуализации сложных архитектурных взаимосвязей, потоков данных между станками ЧПУ и серверами маршрутизации LLM, агент использует встроенный генеративный инструмент "Nano Banana 2", который автономно отрисовывает системные диаграммы. Параллельно настраивается логика динамической генерации сертификатов MDR: система программируется на автоматическое создание PDF-паспортов для каждого обработанного заказа, куда вносятся данные о номере лота циркониевого диска, температурных профилях синтеризации и детальные логи оркестрации искусственного интеллекта, что обеспечивает абсолютную прослеживаемость производственного цикла.  
Документация самого проекта формируется в универсальном формате Markdown и подготавливается для публикации. Агент-писатель инициализирует локальный репозиторий Git, создает специализированную директорию docs/ или ветку gh-pages и размещает в ней структуру проекта. Эта база знаний включает инструкции по конфигурации режимов работы (Fully Autonomous и Supervised Review), детальный справочник API для всех созданных узлов MCP, а также описание логики поведения субагентов, извлеченное из файлов AGENTS.md. Используя преднастроенные токены авторизации CI/CD, агент автоматически формирует коммиты и выполняет отправку изменений в удаленный репозиторий GitHub, развертывая Wiki-страницы проекта в автоматическом режиме.  
Завершающим аккордом выступает финальная сборка комплекса. DevOps-агент берет на себя ответственность за инкапсуляцию всех подсистем — клиентского дашборда на Three.js, бэкенда FastMCP, серверов маршрутизации LLM и контейнеров с базами данных — в единый декларативный конфигурационный файл docker-compose.dental-ai.yml. После сборки образов инициируется финальный дымовой тест (Smoke Test): система получает эталонный 3D-скан челюсти и должна в полностью автономном режиме провести его через все стадии обработки. Успешная генерация валидного G-кода, формирование PDF-паспорта и штатный ответ цифровых двойников телеметрии служат подтверждением готовности комплекса. При успешном прохождении верификации проект маркируется как релиз-кандидат и автоматически публикуется в локальном реестре лаборатории.
