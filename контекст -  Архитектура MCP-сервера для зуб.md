Для формирования архитектуры специализированного MCP-сервера и подбора релевантных открытых моделей геометрического анализа сеток был выполнен поиск по актуальным инженерным и научным репозиториям (*MICCAI 3DTeethSeg, Teeth3DS+, CrownGen, MeshSegNet, FastMCP*).  
**Шаги проектирования архитектуры:**

> 1. **Декомпозиция зуботехнического пайплайна** на дискретные математические и производственные задачи: сегментация скана \\rightarrow определение границы уступа (Margin Line) \\rightarrow генерация анатомии (Crown CAD) \\rightarrow создание цоколя/штампика (Model Builder) \\rightarrow подготовка метаданных и нестинг (CAM).  
> 2. **Формирование MCP-интерфейса:** проектирование примитивов Model Context Protocol (Tools, Resources, Prompts) для обеспечения взаимодействия AI-агентов с локальными CLI/Python-библиотеками и headless-движками.  
> 3. **Подбор локального AI/ML-стека:** анализ доступных легковесных и специализированных 3D-нейросетей на базе PyTorch для работы с полигональными сетками (Mesh) и облаками точек (Point Cloud) без обращения к закрытым облакам.  
> 4. **Спецификация интеграционных скриптов и обвязок:** разработка модулей взаимодействия с Blender (bpy), libigl, trimesh и CAM-системами (*MillBox / hyperDENT*).

### **Краткий вывод**

Архитектура системы строится вокруг **dental-cadcam-mcp-server** (на базе Python FastMCP), выступающего единой шиной данных между оркестратором AI-агентов и локальным вычислительным контуром.  
Стек полностью автономен и состоит из:

> 1. **Локального AI-ядра:** 3D-нейросети сегментации (*Teeth3DS+ / MeshSegNet*), экстракции уступа и диффузионной генерации анатомии (*CrownGen*), обслуживаемых через PyTorch/Triton.  
> 2. **Геометрического движка:** Python-обвязка (trimesh, libigl, open3d) и Headless Blender (bpy) для булевых операций, создания цоколей и расчета зазора цемента.  
> 3. **CAM/ЧПУ-коннектора:** Генератор нативных метаданных (.constructionInfo / XML) и автоматизатор нестинга для 5-осевого фрезера.

### **Содержание**

> 1. Архитектурный каркас MCP-сервера (dental-cadcam-mcp)  
> 2. Локальные нейросетевые модели (AI/ML Core), дообучение и обвязка  
> 3. Инженерные скрипты и алгоритмические обвязки (Headless Blender & Geometry Core)  
> 4. Агентная структура и оркестрация (Multi-Agent Architecture)  
> 5. CAM, ЧПУ-интеграция и контроль станка  
> 6. Инфраструктура, зависимости и стек развертывания

### **1\. Архитектурный каркас MCP-сервера (dental-cadcam-mcp)**

Сервер реализуется на базе **Python (FastMCP / AsyncIO)** и обменивается данными с LLM-агентами по протоколу JSON-RPC (транспорты: stdio для локальных агентов в IDE/CLI или SSE/Streamable HTTP для распределенной сети).  
   `┌──────────────────────────────────────────────────────────────────┐`  
   `│                       AI AGENT ORCHESTRATOR                      │`  
   `└───────────────────────────────┬──────────────────────────────────┘`  
                                   `│ (Model Context Protocol: JSON-RPC)`  
   `┌───────────────────────────────▼──────────────────────────────────┐`  
   `│                   DENTAL MCP SERVER (FastMCP)                    │`  
   `├───────────────────┬──────────────────────────┬───────────────────┤`  
   `│     MCP TOOLS     │      MCP RESOURCES       │    MCP PROMPTS    │`  
   `│  (Команды агента) │  (3D Сетки, Метаданные)  │ (Шаблоны диалога) │`  
   `└─────────┬─────────┴────────────┬─────────────┴─────────┬─────────┘`  
             `│                      │                       │`  
 `┌───────────▼──────────┐ ┌─────────▼─────────┐ ┌───────────▼─────────┐`  
 `│   Local AI Engine    │ │ Geometry / Blender│ │   CAM / CNC Driver  │`  
 ``│ (MeshSeg / CrownGen) │ │   (`bpy` Headless)│ │(MillBox / hyperDENT)│``  
 `└──────────────────────┘ └───────────────────┘ └─────────────────────┘`

#### **Категория 1.1: MCP Tools (Инструменты, вызываемые агентами)**

> * parse\_ios\_scan(scan\_path: str, jaw: "upper"|"lower") \-\> MeshInfo: Чтение STL/PLY, валидация замкнутости сетки (*manifold*), расчет площади, количества полигонов и проверка дефектов сканирования.  
> * segment\_dental\_arch(scan\_path: str) \-\> SegmentationResult: Запуск локальной 3D-нейросети. Возвращает массив зубов с маркировкой по номенклатуре **FDI (11–48)** и выделенной десной (*gingiva*).  
> * detect\_margin\_line(prep\_tooth\_mesh\_id: int) \-\> MarginCurve: Автоматическая экстракция замкнутой 3D-кривой уступа препарированного зуба с субмиллиметровой точностью.  
> * generate\_crown\_anatomy(prep\_mesh\_id: int, antagonist\_mesh\_id: str, fdi: int) \-\> CrownMesh: Генерация монолитной анатомической коронки с предварительной окклюзионной подгонкой.  
> * build\_printable\_model(scan\_path: str, base\_type: "hollow"|"solid", drain\_holes: bool) \-\> Model3D: Генерация цокольной разборной 3D-модели со штампиками (*dies*) для печати на 3D-принтере.  
> * generate\_cam\_metadata(crown\_path: str, margin\_curve: list, insertion\_axis: list) \-\> ConstructionInfo: Формирование .constructionInfo и XML для автоматического импорта в MillBox/hyperDENT.  
> * generate\_mdr\_passport(order\_id: str, disk\_lot: str, material: str) \-\> PDFPath: Автоматическое создание паспорта медицинского изделия по регламенту MDR (EU 2017/745).

#### **Категория 1.2: MCP Resources (Ресурсы контекста)**

> * dental://orders/{order\_id}/metadata: JSON-схема заказа (врач, клиника, дата сдачи, цвет VITA, материал: цирконий HT/ML/3D Pro, номер зуба).  
> * dental://scans/{order\_id}/upper\_mesh: Доступ к сырым и предобработанным 3D-сеткам верхней челюсти.  
> * dental://scans/{order\_id}/lower\_mesh: Доступ к 3D-сеткам нижней челюсти.  
> * dental://telemetry/milling\_machine: Телеметрия 5-осевого фрезера (статус шпинделя, процент выполнения G-кода, износ боров).

#### **Категория 1.3: MCP Prompts (Контекстные шаблоны)**

> * inspect\_margin\_integrity: Промпт для мультимодального агента по оценке правильности прохождения границы препарирования по кривизне уступа.  
> * resolve\_occlusal\_penetration: Шаблон инструкций для оптимизации межокклюзионных контактов с зубом-антагонистом (допустимое внедрение: \-0.05 мм, толщина циркония \\ge 0.6 мм).

### **2\. Локальные нейросетевые модели (AI/ML Core), дообучение и обвязка**

Вместо облачных API разворачиваются специализированные легковесные 3D-сети (PyTorch), оптимизированные через TensorRT/ONNX Runtime.

#### **Категория 2.1: Модели сегментации зубных рядов (Tooth Segmentation)**

> * **Архитектура:** **MeshSegNet** (Multi-Scale Graph CNN) или **DilatedToothSegNet** на базе открытого бенчмарка **Teeth3DS+ (MICCAI)**.  
> * **Входные данные:** 3D-сетка (VTP/PLY) интраорального скана (вершины, грани, нормали ячеек).  
> * **Выход:** FDI-лейблинг каждой грани (от 11 до 48 \+ 0 для десны) и выделение индексов треугольников препарированного зуба.  
> * **Обвязка:** Сервис на FastAPI / Triton Inference Server, принимающий файл через shared memory и отдающий JSON-массив индексов граней.

#### **Категория 2.2: Модель детекции границы уступа (Margin Line Extraction)**

> * **Архитектура:** Двухэтапная гибридная модель:  
  1. *Сегментатор переходной зоны:* Mesh-based CNN, разделяющая культю на верхнюю (коронковая) и нижнюю (поддесневая) зоны.  
  2. *Геодезический сплайн:* Алгоритм поиска пути минимальной стоимости (Dijkstra/Fast Marching на взвешенном графе кривизны) вдоль границы разделения зон.  
> * **Точность:** Отклонение \\le 25 мкм от ручной разметки техника.

#### **Категория 2.3: Генеративная модель анатомии коронки (Generative CAD)**

> * **Архитектура:** **CrownGen** (Denoising Diffusion Probabilistic Model на облаках точек зуба) или параметрическая модель морфинга **Statistical Shape Model (SSM)**.  
> * **Входные данные:** Пространственные границы (культя, апроксимальные соседние зубы, плоскость смыкания антагониста).  
> * **Выход:** Восстановленная окклюзионная и вестибулярная поверхность коронки с сохранением анатомических бугров и фиссур.  
> * **Дообучение:** Дообучение на датасетах библиотек зубов (Michael Tholey, VITA, открытые библиотеки оцифрованных естественных зубов).

#### **Категория 2.4: Vision-Language модель визуального контроля (QA VLM)**

> * **Модель:** **MiniCPM-V 2.6** или **Qwen2.5-VL-7B-Instruct** (квантование 4-bit/AWQ).  
> * **Задача:** Агент делает рендеринг 3D-модели коронки в 4 проекциях (окклюзионная, вестибулярная, мезиальная, сагиттальный срез посадки на культю) и передает картинки VLM. Модель оценивает толщину стенок (тепловая карта), наличие поднутрений (*undercuts*) и чистоту прилегания края.

### **3\. Инженерные скрипты и алгоритмические обвязки (Headless Blender & Geometry Core)**

Математический базис для операций над полигональными сетками, не требующий ручного участия.

#### **Категория 3.1: Python Geometry Core (trimesh, libigl, open3d)**

> * mesh\_cleaner.py:  
  * Удаление изолированных вершин, дубликатов граней, незамкнутых ребер (*non-manifold edges*).  
  * Сглаживание шумов сканирования алгоритмом Лапласа с сохранением острых граней (*feature-preserving Taubin smoothing*).  
> * margin\_postprocessor.py:  
  * Аппроксимация облака точек уступа в B-сплайн Безье.  
  * Проверка кривизны и устранение «петель» и заломов кривой.  
> * cement\_spacer\_builder.py:  
  * Смещение внутренней поверхности коронки (Offset) для формирования цементного зазора (30–40 мкм).  
  * Параметрическое создание защитной краевой полосы (0.5–1.0 мм от линии уступа с зазором 0 мкм для идеального краевого прилегания).

#### **Категория 3.2: Headless Blender Scripts (blender \-b \-P)**

> * base\_model\_builder.py:  
  * Автоматическое закрытие дна интраорального скана, формирование стандартного цоколя (American / Horseshoe base).  
  * Полая выборка (*Hollowing*) с толщиной стенки 2.0 мм для экономии фотополимера.  
  * Врезка дренажных каналов и гравировка номера заказа / фамилии пациента текстом через булево вычитание.  
> * die\_ditcher.py:  
  * Создание съемного штампика (*removable die*) препарированного зуба с направляющим пином (*pin*) для контроля посадки.  
> * occlusal\_carver.py:  
  * Автоматическое булево вычитание зуба-антагониста из окклюзионной поверхности коронки с учетом заданного клиренса динамической артикуляции.

#### **Категория 3.3: CAM Metadata Exporter**

> * exocad\_bridge.py:  
  * Генерация файла .constructionInfo (XML/JSON), содержащего векторы MarginLine, InsertionAxis и MaterialIdentifier.  
  * Позволяет CAM-системам (MillBox, hyperDENT, SUM3D) подхватывать STL как родной проект Exocad без ручной прорисовки границ оператором.

### **4\. Агентная структура и оркестрация (Multi-Agent Swarm)**

Оркестрация на базе **LangGraph** или **Autogen**, где каждый агент наделен узкой ролью и специфическим набором MCP-инструментов.  
                  `┌──────────────────────┐`  
                  `│  Order Ingestion     │ (Парсинг email/мессенджера/FTP клиники)`  
                  `└──────────┬───────────┘`  
                             `│`  
                  `┌──────────▼───────────┐`  
                  `│  Orchestrator Agent  │ <── Управляет жизненным циклом заказа`  
                  `└──────────┬───────────┘`  
         `┌───────────────────┼───────────────────┐`  
         `│                   │                   │`  
`┌────────▼────────┐ ┌────────▼────────┐ ┌────────▼────────┐`  
`│  CAD Specialist │ │   QA & Review   │ │  CAM & Nesting  │`  
`│      Agent      │ │   (VLM Agent)   │ │      Agent      │`  
`└────────┬────────┘ └────────┬────────┘ └────────┬────────┘`  
         `│                   │                   │`  
         `└───────────────────┼───────────────────┘`  
                             `│`  
                  `┌──────────▼───────────┐`  
                  `│ MDR Compliance Agent │ (Генерация паспорта изделия и фактуры)`  
                  `└──────────────────────┘`

> * **CAD Specialist Agent:** Принимает сканы, вызывает segment\_dental\_arch, определяет культю, запрашивает detect\_margin\_line и generate\_crown\_anatomy, соединяет геометрию и генерирует STL.  
> * **QA & Review Agent (VLM):** Проводит инспекцию: строит срезы коронки, анализирует толщину стенки в фиссурах (критический минимум \> 0.6 мм для циркония) и подтверждает готовность к производству или отправляет CAD-агенту запрос на правку.  
> * **CAM & Nesting Agent:** Выбирает оптимальный циркониевый диск из склада (по высоте, цвету VITA и остатку свободного места), запускает скрипт нестинга, ориентирует поддержки (*sprues*) вне зоны режущего края и уступа, генерирует G-код.  
> * **MDR Compliance Agent:** Логирует номер партии сырья (LOT циркониевого диска), фиксирует контрольные параметры и формирует готовую PDF-декларацию соответствия европейскому регламенту.

### **5\. CAM, ЧПУ-интеграция и контроль станка**

#### **Категория 5.1: Автоматизация нестинга (CAM Automation)**

> * **MillBox COM/CLI API:** Передача параметров через конфигурационные файлы .xml:  
  * Автоматический импорт STL \+ .constructionInfo.  
  * Авто-размещение в диске с оптимизацией высоты (Multi-layer градиент цвета).  
  * Автоматическая расстановка удерживающих перемычек (*connectors/sprues*) диаметром 1.2 мм с безопасным отступом от границы препарирования.  
> * **Открытый стек (Альтернатива для простых задач):** На базе FreeCAD Path / custom 5-axis toolpath generator на C++/Python для стандартных профилей обточки.

#### **Категория 5.2: Мониторинг и управление оборудованием**

> * **Hardware Bridge (cnc\_bridge.py):**  
  * Мониторинг состояния фрезера по сетевому протоколу (Modbus TCP / OPC UA / Ethernet-интерфейс стойки ЧПУ).  
  * Считывание датчика давления воздуха (минимум 6 бар) и уровня охлаждающей жидкости/вытяжки перед запуском.  
  * Очередь отправки G-кода на станок для ночного фрезерования (Batch Queue).
